## Предметная область

Система предназначена для учёта посещаемости занятий студентами.

В системе предполагается хранить информацию о:

- студентах;
- учебных группах;
- занятиях;
- фактах присутствия и отсутствия студентов.

Для посещаемости предусмотрены статусы:
«присутствовал», «отсутствовал»,
«уважительная причина».

## Цели системы

1. Автоматизировать отметку посещаемости.
2. Обеспечить хранение и быстрый доступ к данным.
3. Позволить студентам отслеживать свою посещаемость.
4. Формировать отчёты по группе и отдельному студенту за период.
5. Снизить количество ошибок по сравнению с бумажным учётом.

## Пользователи системы

| Пользователь | Планируемые возможности |
|---|---|
| Преподаватель | Создание занятий, отметка посещаемости, просмотр отчётов по своей группе и отдельным студентам, экспорт отчётов |
| Студент | Просмотр и экспорт только собственной посещаемости |
| Администратор | Управление студентами и группами, просмотр и экспорт отчётов по группам и отдельным студентам |

## Планируемые функции

- Добавление и редактирование студентов.
- Добавление и редактирование групп.
- Создание занятия с указанием даты, группы и преподавателя.
- Отметка посещаемости.
- Просмотр студентом своей посещаемости с фильтрацией по дате.
- Формирование отчёта по группе за выбранный период.
- Формирование отчёта по отдельному студенту за выбранный период.
- Экспорт отчётов в CSV или JSON.

## Лабораторная работа №3 — база данных SQLite

Подготовлена база данных системы учёта посещаемости занятий студентами.
Приложение работает на Python; SQLite вызывается стандартным модулем sqlite3.

### ER-диаграмма

![ER-диаграмма базы данных](diagrams/er_sqlite_users.png)

[Исходник PlantUML](diagrams/er_sqlite_users.puml) · [SVG](diagrams/er_sqlite_users.svg)

### Таблицы

| Таблица | Назначение | Первичный ключ | Внешние ключи |
|---|---|---|---|
| groups | Учебные группы | group_id | — |
| teachers | Преподаватели | teacher_id | — |
| students | Студенты и их группы | student_id | group_id → groups |
| lessons | Дата, группа и преподаватель занятия | lesson_id | group_id → groups; teacher_id → teachers |
| attendance | Отметки посещаемости | attendance_id | lesson_id → lessons; student_id → students |
| users | Учётные записи и роли | user_id | student_id → students; teacher_id → teachers |

Идентификаторы имеют тип INTEGER, остальные поля — TEXT.
Дата хранится в формате YYYY-MM-DD.
Типы атрибутов, PK/FK и кратности связей показаны на диаграмме.

Группа связана со студентами и занятиями отношением 1:N, преподаватель
с занятиями — 1:N. Связь студентов и занятий M:N реализована через attendance.
Студент и преподаватель могут иметь по одной учётной записи: связь с users
необязательная 1:1, то есть 0..1 с обеих сторон. UNIQUE запрещает несколько
учётных записей для одного и того же студента или преподавателя.

Роли пользователей: admin, teacher, student. Администратор хранится в users
с role = 'admin', student_id = NULL и teacher_id = NULL.
Для преподавателя заполнен только teacher_id, для студента — только student_id.
Согласованность роли и ссылки проверяется ограничением CHECK.
Полномочия ролей будут проверяться в коде приложения при реализации входа.

Ограничение UNIQUE (lesson_id, student_id) исключает повторную отметку.
Статусы ограничены CHECK: present, absent, excused.
Отсутствие строки attendance означает, что отметка ещё не внесена.
Прямые SQL-вставки не проверяют совпадение группы студента и занятия:
эта бизнес-проверка потребуется при реализации отметки посещаемости.

### Реализация

- schema_sqlite.sql — CREATE TABLE и ограничения.
- seed_sqlite.sql — INSERT INTO с учебными группами, студентами, преподавателями,
  занятиями и отметками.
- src/database_sqlite.py — открытие файла БД и включение внешних ключей.
- src/init_sqlite.py — выполнение SQL-скриптов и INSERT INTO с учётными записями.
- src/check_sqlite.py — проверка таблиц, ролей, связей и выборки посещаемости.
- src/main.py — общий запуск практической части.

### Запуск

В PyCharm запустить src/main.py через Run 'main'. Из корня проекта:

```bash
python src/main.py
```

Создаётся файл data/attendance_lab3.db. Повторный запуск сохраняет
существующие записи и не дублирует тестовые данные.
Данные вымышленные. В каждой таблице несколько записей:

```text
groups: 2
teachers: 2
students: 4
lessons: 4
attendance: 8
users: 7
```

Для users сохраняются хеши учебного пароля Demo123!.
Этот пароль используется только для заполнения учебных учётных записей.

### Проверка

В выводе программы должно быть:

```text
Проверка внешних ключей включена: 1
Нарушения внешних ключей: []
```

Проверены создание базы, повторный запуск, сохранение исправленных отметок,
запрет несуществующих ссылок, повторных отметок, некорректной привязки роли
и нескольких учётных записей для одного студента.
